# Anilibrary — особистий трекер аніме

Статичний сайт (GitHub Pages) з даними у Firebase. Назви й описи українською беруться з TMDB, серії та розклад з AniList.
Без фреймворків і збирачів: HTML, CSS і JS-модулі.

**Можливості**
- вхід через Google; редагує тільки власник, друга людина має доступ лише на перегляд;
- головна: «Є нові серії» (що вийшло понад переглянуте) і «Скоро вийде»;
- календар: сітка місяця з крапками на днях виходу серій (дивлюсь / чекаю сезон) і список серій вибраного дня;
- поради: схожі тайтли за рекомендаціями глядачів AniList на основі переглянутого (ваша оцінка підсилює схожі);
- списки за статусами: дивлюсь, чекаю сезон, заплановано, переглянуто, кинуто; пошук за назвою;
- картка тайтлу: прогрес (сезон і серія), статус, посилання, оцінка, нотатка, видалення;
- додавання через пошук TMDB;
- експорт та імпорт JSON (бекап);
- PWA: можна додати на головний екран телефона чи планшета.

## Структура

```
index.html              — оболонка сторінки й навігація
css/style.css           — стилі (темна тема, mobile-first)
js/config.js            — ключі Firebase, uid, ключ TMDB   ← заповнити
js/db.js                — Firebase: вхід і Firestore
js/tmdb.js              — TMDB: пошук, українські назви й описи, запасний розклад
js/anilist.js           — AniList: серії, розклад, наступні сезони
js/app.js               — екрани й роутинг
manifest.webmanifest    — PWA
icons/                  — іконки
firestore.rules         — правила доступу до бази          ← вставити uid
.nojekyll               — щоб GitHub Pages віддавав файли як є
```

## Налаштування крок за кроком

### 1. Ключ TMDB

1. Зареєструйтеся на <https://www.themoviedb.org/signup>.
2. Відкрийте **Settings → API** (<https://www.themoviedb.org/settings/api>) і подайте заявку на ключ (тип *Developer*, мета: особистий некомерційний проєкт).
3. Скопіюйте **API Key** (це ключ v3, короткий рядок, а не довгий «Read Access Token»).
4. Вставте його в `js/config.js` → `TMDB_API_KEY`.

### 2. Проєкт Firebase

1. Відкрийте <https://console.firebase.google.com> → **Add project / Створити проєкт**. Google Analytics можна вимкнути.
2. На головній сторінці проєкту натисніть іконку **</>** (Web), щоб додати вебзастосунок. Назва довільна, Firebase Hosting не потрібен.
3. Скопіюйте об'єкт `firebaseConfig` і перенесіть значення в `js/config.js` (`apiKey`, `authDomain`, `projectId`, `storageBucket`, `messagingSenderId`, `appId`).
   Потім ці дані можна знайти в **Project settings (⚙) → General → Your apps**.

> Ключі Firebase і TMDB у клієнтському коді будуть публічними, і для статичного сайту це нормально.
> Базу захищають правила Firestore (крок 5), а не секретність ключа.

### 3. Вхід через Google

1. **Build → Authentication → Get started**.
2. Вкладка **Sign-in method** → **Google** → **Enable**. Вкажіть email підтримки → **Save**.

### 4. Firestore

1. **Build → Firestore Database → Create database**.
2. Регіон: наприклад, `eur3 (europe-west)`. Режим: **Production mode**.

### 5. Деплой на GitHub Pages

1. Створіть репозиторій на GitHub, наприклад `anilibrary`.
2. Завантажте в нього вміст цієї папки:
   ```bash
   git init
   git add .
   git commit -m "Anilibrary"
   git branch -M main
   git remote add origin https://github.com/<ваш-логін>/anilibrary.git
   git push -u origin main
   ```
3. У репозиторії відкрийте **Settings → Pages**. Source: **Deploy from a branch**, Branch: `main`, папка: `/ (root)` → **Save**.
4. Через хвилину-дві сайт з'явиться за адресою `https://<ваш-логін>.github.io/anilibrary/`.

### 6. Домен GitHub Pages в Authorized domains

Без цього вхід через Google на сайті не спрацює.

1. Firebase Console → **Authentication → Settings → Authorized domains → Add domain**.
2. Додайте `<ваш-логін>.github.io` (тільки домен, без `https://` і без шляху).
   `localhost` там уже є, тому локальний запуск працює одразу.

### 7. Дізнатися свій uid (і uid другої людини)

Найпростіший спосіб:
1. Відкрийте сайт і увійдіть через Google.
2. Поки uid не прописано в налаштуваннях, ви побачите екран «Немає доступу» з вашим uid і кнопкою «Копіювати uid».
3. Друга людина робить те саме на своєму пристрої й надсилає вам свій uid.

Інший спосіб: після першого входу uid видно в Firebase Console → **Authentication → Users**, колонка **User UID**.

### 8. Вписати uid

1. У `js/config.js`:
   ```js
   export const OWNER_UID = 'ваш uid';
   export const READER_UID = 'uid другої людини';
   ```
2. У `firestore.rules` замініть `OWNER_UID_ТУТ` і `READER_UID_ТУТ` на ті самі значення.
3. Firebase Console → **Firestore Database → Rules**: вставте вміст `firestore.rules` → **Publish**.
4. Закомітьте й запуште зміни:
   ```bash
   git commit -am "uid" && git push
   ```

Готово: оновіть сторінку сайту (GitHub Pages оновлюється з затримкою до кількох хвилин).

> uid у `config.js` керує лише інтерфейсом, тобто показом кнопок редагування.
> Реальний захист дають правила Firestore: навіть якщо хтось змінить код у браузері, писати в базу зможе тільки власник.

## Локальний запуск

ES-модулі не працюють, якщо відкрити `index.html` подвійним кліком. Потрібен будь-який локальний сервер:

```bash
npx serve .
```
або
```bash
python -m http.server 8000
```

Потім відкрийте `http://localhost:8000` (або адресу, яку покаже `serve`).

## Додати на головний екран (PWA)

- **Android (Chrome):** меню ⋮ → «Додати на головний екран» / «Установити застосунок».
- **iPhone / iPad (Safari):** кнопка «Поділитися» → «На екран “Додому”».
- **ПК (Chrome / Edge):** іконка встановлення в адресному рядку.

## Звідки дані: TMDB + AniList

| | TMDB | AniList |
|---|---|---|
| Пошук при додаванні, українська назва й опис, постер | ✔ | |
| Скільки серій вийшло, коли наступна (з точним часом) | запасний варіант | ✔ |
| Вихід наступного сезону | | ✔ |

На AniList кожен сезон аніме є окремим записом зі своєю нумерацією серій (1, 2, 3…), як на сайтах для перегляду.
Тайтл у списку прив'язується до запису **поточного сезону**:

- При додаванні запис AniList підбирається автоматично, зазвичай це перший сезон.
  Якщо дивитесь, наприклад, 3 сезон, відкрийте картку тайтлу → блок **AniList** → **Змінити** і виберіть потрібний запис.
- **Прогрес** — це номер сезону (ваш лік) і номер серії **в межах прив'язаного запису AniList**.
- Коли поточний сезон закінчився і ви все переглянули, а на AniList вийшов сіквел, на головній з'явиться блок
  «Вийшов новий сезон» з кнопкою **«Почати сезон N+1»**. Вона перев'язує тайтл на новий запис і скидає прогрес на SN+1E0.
  Якщо сіквел лише анонсовано, він буде в блоці «Скоро вийде».
- Без прив'язки (кнопка **«Відв'язати»** або якщо AniList нічого не знайшов) нові серії рахуються за TMDB:
  прогрес порівнюється як пара (сезон, серія) за нумерацією TMDB, а на картці показано, скільки серій у кожному сезоні.
  «+1 серія» після останньої серії сезону сама переходить на наступний сезон TMDB.

Відповіді обох сервісів кешуються в localStorage на `CACHE_HOURS` годин (за замовчуванням 6).
Примусово оновити дані можна в «Ще → Оновити зараз». Для AniList ключ не потрібен.

## Бекап

«Ще → Експорт у JSON» завантажує файл `anilibrary-РРРР-ММ-ДД.json` з усім списком.
«Імпорт з JSON» (тільки для власника) додає тайтли з файлу. Тайтли з таким самим `tmdbId` будуть перезаписані, решта списку залишиться без змін.

## Структура документа в Firestore

Колекція `anime`, id документа дорівнює `tmdbId`:

```js
{
  tmdbId: 1429,
  anilistId: 16498,            // запис поточного сезону на AniList або null
  title: 'Атака титанів',
  originalTitle: '進撃の巨人',
  poster: 'https://image.tmdb.org/t/p/w342/....jpg',
  overview: '...',
  status: 'watching',          // watching | completed | planned | dropped | waiting
  progress: { season: 1, episode: 7 },   // остання переглянута серія (серія — за записом AniList)
  watchUrl: 'https://...',
  rating: 9,                   // 1–10 або null
  note: '',
  addedAt: 1731000000000,      // мс з 1970 року
  updatedAt: 1731000000000
}
```
